# Post-capstone full HEBO and TuRBO-1 comparison

**This code was added after the 13-round challenge.** It does **not** replace or retroactively claim to have generated the historical capstone queries.

The original project used [HEBO-inspired and TuRBO-style experiments](../../src/bbo/optimizer.py). This folder provides a separately labelled, reproducible **reference comparison** using (a) the **official HEBO Python package** and (b) a **BoTorch/GPyTorch TuRBO-1 implementation** based on the published BoTorch tutorial.

[Main source: benchmark.py](benchmark.py) · [Code walkthrough](../../docs/methods.md) · [Unit tests](test_benchmark.py) · [Experiment status](README.md)

## Study design

| Test | Same data | Same evaluation budget | Objective feedback | Valid conclusion |
|---|---|---|---|---|
| F8 simulated closed loop | 40 initial F8 observations | 12 new evaluations each, per seed | **Fitted quadratic model only** | Relative sample efficiency on the F8 **simulator**, not the private portal |
| One-step proposals, F1–F8 | Each function's own observations through Week 9 | One unscored proposal per engine | **No feedback** | Candidate locations, legal-domain constraints and distance from past points |

The F8 surrogate is trained on **40 initial observations** and checked against **13 later portal returns** without using them for training. Its 17 coefficients and held-out accuracy support a useful test model. They do not prove the unknown source formula everywhere.

HEBO minimises. Our capstone maximises. The reference code passes **negative scores** to the official HEBO `observe()` method, including feedback after each *simulated* evaluation.

TuRBO-1 uses lengthscale-weighted ARD Matérn regions, Thompson sampling, feedback-based expansion/shrinkage and budgeted restart initialisations. The initial 40 F8 observations were not generated by TuRBO, so this is a **warm-started TuRBO-1 comparison**, not an authentic replay of native TuRBO initialisation.

## Run the optional comparison from GitHub Actions

The [manual HEBO / TuRBO-1 benchmark workflow](https://github.com/tatonsyML/bbo-capstone-imperial-college/actions/workflows/full-optimisers.yml) runs the two engines in separate Python environments, stores both sets of **model-simulated** F8 results and produces a downloadable comparison artifact only after equal-budget checks. Use **Run workflow** to select a budget and `f8`, `proposals` or `all`.

This is post-capstone research, not historical query-selection code. Any upstream package or model failure is exposed rather than silently replaced with a lightweight imitation.

## Run the dependency-free unit tests

From the capstone repository root, with NumPy, pandas and pytest installed:

```bash
python -m pytest -q research/full_optimisers/test_benchmark.py
```

The tests check F8 held-out reconstruction, the 17-feature basis, six-decimal bounds, TuRBO length adaptation and fair-budget rejection. They do **not** execute HEBO or BoTorch.

## Run the full algorithms

Because older official HEBO versions and current BoTorch/GPyTorch releases have different dependency needs, **use two fresh virtual environments if their dependencies conflict**. Python 3.10 or 3.11 is a reasonable starting point; verify versions in your environment.

**HEBO environment:**

```bash
python -m venv .venv-hebo
source .venv-hebo/bin/activate
python -m pip install -r research/full_optimisers/requirements-hebo.txt
python research/full_optimisers/benchmark.py --engine hebo --mode all --budget 12 --seeds 0 1 2
deactivate
```

**BoTorch TuRBO-1 environment:**

```bash
python -m venv .venv-turbo
source .venv-turbo/bin/activate
python -m pip install -r research/full_optimisers/requirements-turbo.txt
python research/full_optimisers/benchmark.py --engine turbo --mode all --budget 12 --seeds 0 1 2
deactivate
```

**Compare only after both runs complete:**

```bash
python research/full_optimisers/benchmark.py --mode compare
```

On Windows, activate the environments using the appropriate `.venv-*/Scripts/activate` command. To reduce run time for a smoke test, run `--mode f8 --budget 2 --seeds 0` in both environments. Avoid treating that tiny budget as a meaningful algorithm ranking.

The default output folder is `results/full_hebo_turbo/`. Results will include:

| Generated file | Meaning |
|---|---|
| `versions_hebo.csv`, `versions_turbo.csv` | Runtime package versions |
| `f8_oracle_validation.csv` | 40/13 split, holdout error and fitted optimum |
| `f8_simulation_hebo.csv`, `f8_simulation_turbo.csv` | **Simulated** paid queries and feedback |
| `f8_simulation_comparison.csv` | Equal-budget comparison of the two recorded simulations |
| `one_step_proposals_hebo.csv`, `one_step_proposals_turbo.csv` | **Unscored** counterfactual suggestions |

## Evidence controls

- All candidates are rounded and clipped to the permitted **six-decimal portal domain** before simulated evaluation.
- A repeated query still consumes one unit of the simulated budget.
- TuRBO's new local starts consume paid simulated evaluations; it does not reset the budget.
- Actual later F8 returns are **validation only**, not training data or simulated feedback.
- Outputs use prominent `SIMULATED_` column names.
- Do not merge peers' public data into personal observations.
- A run is incomplete if an optional package is absent; **do not invent or prepopulate result CSVs**.

**Status in this repository:** reference code and unit tests added. The complete HEBO and BoTorch reference algorithms **have not yet been executed for a published comparison**. No comparative numerical performance claim is made.
